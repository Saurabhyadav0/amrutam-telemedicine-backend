# Agent guide: Amrutam telemedicine backend

Instructions for AI coding agents (and humans) working in this repo. Read this first, then
the skill for the task at hand from `.agents/skills/`.

## What this is

Python 3.12 + FastAPI backend for Amrutam's Ayurvedic teleconsultations: auth/MFA/RBAC,
doctor onboarding and availability, booking saga with payments, consultations, signed
e-prescriptions, admin analytics, audit and DPDP privacy rights. PostgreSQL 16 + Redis 7;
an arq worker runs outbox delivery, saga timeouts, refunds and rollups. Architecture:
`docs/architecture.md`. Security and compliance: `docs/security.md`, `docs/compliance.md`.

## Commands

```bash
make env && make up        # full local stack (API x4 behind gateway, worker, Postgres, Redis, observability)
make smoke                 # 42 end-to-end checks against the running stack
make test                  # unit + integration tests on real Postgres/Redis (coverage gate 80%)
make lint typecheck security
make openapi               # regenerate docs/openapi.yaml after any API change (CI checks it)
make tf-check              # terraform fmt/validate + Checkov
make seed-load && make load  # k6 peak-hour mix with SLO thresholds
```

## Rules (non-negotiable)

1. **Layering:** `router → service → repository → models`. Services get collaborators by
   injection and never import FastAPI. See `amrutam-backend`.
2. **One transaction per state change**, including its audit record and outbox event.
   Side effects go through the outbox; handlers are idempotent.
3. **Invariants live in Postgres** (constraints, exclusion constraints, compare-and-set
   updates, `ON CONFLICT`, `SKIP LOCKED`), backed by a concurrency test.
4. **Idempotency:** writes honour `Idempotency-Key`; require it where duplicates hurt.
5. **PHI** is field-encrypted with a row-bound AAD and never appears in logs, audit
   metadata, events, notifications or error bodies. Non-participants get 404.
6. **No secrets in the repo.** Config comes from env vars validated at startup; `.env` is
   git-ignored and generated by `make env`.
7. **Migrations** are additive, hand-numbered, and split into one statement per
   `op.execute` (asyncpg).
8. **Never** add UPDATE/DELETE paths on `audit_logs` or `prescriptions`, weaken MFA for
   privileged roles, or relax TPG medicine-list checks.
9. **Done means verified:** lint, types, security scan and tests pass; `make smoke` for
   flow changes; `docs/openapi.yaml` regenerated. Don't weaken a test to make it pass.

## Domain glossary

| Term | Meaning |
|---|---|
| **Patient / Doctor / Admin / Support** | User roles. Doctors, admins and support must complete MFA before privileged actions. |
| **Verification** | Admin check of a doctor's registration (number + council, e.g. NCISM) before they are visible or bookable. |
| **Slot** | A doctor's bookable time window: `open` → `held` (checkout, 10 min) → `booked`. Never overlapping per doctor. |
| **Hold** | Temporary reservation of a slot by one patient during payment; released by the sweeper on expiry. |
| **Consultation** | A booked session: `pending_payment → confirmed → in_progress → completed`, or `cancelled` / `no_show`. |
| **Booking saga** | Hold → payment intent → webhook confirm, with compensations (expiry release, refund). |
| **Outbox** | `outbox_events` rows written with a state change and delivered by the worker (at-least-once, backoff, dead letter). |
| **Dead letter (DLQ)** | Outbox event that failed 8 times; visible and retryable at `/v1/admin/outbox`. |
| **TPG lists O / A / B** | Telemedicine Practice Guidelines 2020 medicine lists: O any mode, A video first then refills, B never online. |
| **Signed prescription** | Ed25519 signature over the canonical prescription document; public key at `/v1/prescriptions/signing-key`. |
| **PHI** | Personal health information (complaints, notes, prescriptions, DOB): encrypted at field level. |
| **Audit chain** | Append-only, hash-chained `audit_logs`, monthly partitions; verified at `/v1/admin/audit-logs/verify`. |
| **Rollups** | Daily analytics tables refreshed by the worker; dashboards never scan hot tables. |
| **DPDP rights** | Data export and erasure (`/v1/users/me/data-export`, `/v1/users/me/erasure`); clinical records retained by law. |
